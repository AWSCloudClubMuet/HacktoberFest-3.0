Hackathon Demonstration Guide

This project implements the complete Campus Gig & SkillSwap Portal with a full mock REST API, business rules enforcement, and responsive UI.

1️⃣

Role-Based Demo Selector

Use the demo selector in the top-right navbar to switch identities anytime (14 seeded students). All actions (posting, applying, accepting, reviewing) adapt automatically to the active user.

2️⃣

Complete Gig Lifecycle

Open ➔ In Progress ➔ Completed. Only owners can accept applicants. Accepting an applicant automatically transitions the gig to In Progress and auto-rejects other pending applicants.

3️⃣

Two-Way Peer Reviews

Once a gig is marked Completed, both the gig owner and the accepted applicant can review each other (1-5 stars + feedback). Calculated average ratings update dynamically across the portal!

4️⃣

Backend Rule Enforcement

Duplicate applications are blocked; self-applications are prevented; non-participants cannot submit reviews; invalid status transitions are rejected with HTTP 400/403.

Try this 60-Second Demo Flow:

  1. Switch user to "David Kim" (or any student who is not Alex Rivera).
  2. Browse Explore Gigs and click "View Details" on "Building Responsive Portfolio Websites for Students" (owned by Alex Rivera).
  3. Apply for the gig with a message: "Hi Alex, I need a portfolio for physics research!"
  4. Switch user to "Alex Rivera" in the top navbar.
  5. Open Alex's Dashboard or the gig modal: notice David's pending application. Click "Accept Applicant".
    Gig automatically moves to In Progress.
  6. Click "Mark Gig as Completed".
  7. Submit a review (e.g. 5 stars: "Great collaboration with David!").
  8. Switch back to "David Kim", open the gig, and submit David's review for Alex.
  9. Check the Student Directory: Alex and David's average star ratings and completed gig counts are dynamically updated!

Mock REST API Endpoints

Method Endpoint Description & Business Logic
GET /api/users List users with dynamically computed ratings, review counts, and completed gigs.
GET /api/users/:id Get single user profile, received reviews, and owned gigs.
POST /api/users Register new student profile with skills and major.
PATCH /api/users/:id Update student profile details.
GET /api/gigs Filter gigs by q, category, type, paymentType, status, budget.
POST /api/gigs Create offering or requesting gig with validation.
PATCH /api/gigs/:id Transition status: open ➔ in_progress ➔ completed.
GET /api/applications Filter applications by gigId or applicantId.
POST /api/applications Apply for gig. Rules: blocks self-application & duplicate applications.
PATCH /api/applications/:id Accept or reject applicant. Accepting sets gig to in_progress and auto-rejects others.
GET /api/reviews List reviews filtered by gigId or revieweeId.
POST /api/reviews Submit 1-5 rating & comment. Rules: completed gigs only, participants only, 1 review each.
POST /api/stats/reset Reset database back to initial seed data.
